# BAU Host Provisioning and GitHub App Terraform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cere is provisioned for BAU by the home-infra Cere playbook, `bau.home.nakomis.com` is served by Leia with mTLS, and the GitHub App's installed-repository list is managed by Terraform in `nakomis/bau`.

**Architecture:** Three small, independent deliverables. (1) A `bau` section appended to the existing Cere playbook on the `home-446-cere-playbook` branch (or `main` once that merges): directories, keychain assertions, the repo checkout at `/Users/nakomis/bau/src`, and a call to BAU's own `install.sh`, mirroring how the mac playbook drives the forwarder's installer. (2) One nginx vhost file plus its entry in Leia's playbook list. (3) A Terraform root in `nakomis/bau/terraform` using the `integrations/github` provider authenticated as the App, with `github_app_installation_repository` per repo.

**Tech Stack:** Ansible (home-infra conventions), nginx, Terraform `>= 1.9` with `integrations/github ~> 6.0`.

**Spec:** `docs/superpowers/specs/2026-10-14-bau-design.md`, sections 3, 7 and 15.

## Global Constraints

- home-infra work follows `leia/CLAUDE.md`, `cere/CLAUDE.md` (on the branch) and the repo root `CLAUDE.md`: feature branch, PR, Plane ref in branch and title (HOME project), playbooks run only through `scripts/<host>-ansible.sh`.
- The Cere playbook asserts rather than creates anything needing an Apple ID or interactive sudo. BAU's keychain items are created by Martin at the keyboard; the playbook asserts they exist and fails with the exact `security add-generic-password` command to run.
- Leia's nginx vhost shape is the one in `leia/deployment/nginx/scrutiny.home.nakomis.com.conf`: `ssl_verify_client optional` with the `$ssl_client_verify != "SUCCESS"` guard returning 401, wildcard cert under `/etc/letsencrypt/live/home.nakomis.com/`. No DNS change: `*.home.nakomis.com` already resolves to Leia.
- Cere's LAN address goes in a variable, never hard-coded in the vhost; the vhost is a templated one (`nginx_templated_vhosts`).
- Terraform state for `nakomis/bau/terraform` is local and gitignored, matching `home-infra/infra/terraform`. The App private key is read from the macOS keychain at plan time via an external data source, never committed and never in state.
- Permissions requested on the App (created by hand): contents read/write, pull requests read/write, metadata read, checks read, actions read, administration read (to read branch protection and rulesets). Nothing else.

## Review Focus

1. Running the Cere playbook twice must be idempotent: the `install.sh` call reports `changed` only when the repo moved or the image was rebuilt. Test by a second `--check --diff` run in Task 1.
2. The vhost must return 401 (not 502) to a browser without a client cert, so a missing cert is diagnosed correctly. Verified by `curl -k https://bau.home.nakomis.com/` in Task 2.
3. A repo added to `projects.yaml` but not to the Terraform list: the runner declines with a clear reason (Plan 1 Task 12 covers the decline path when the App cannot mint a token; add the token-mint failure case there as a two-line test if absent).
4. Terraform must refuse to run if the App private key keychain item is missing, with a message naming it. Task 3's external data source exits non-zero with that text.
5. Colima's VM memory: BAU containers running Node plus Claude Code need around 2 GB. The branch's `cere_colima_memory: 3` leaves the CI builds about 1 GB when a BAU session is running at night; bump to 4 in the same PR and note it.

- [ ] **Step 3: Task file `cere/ansible/tasks/bau.yml`**

```yaml
# BAU: the overnight maintenance worker (nakomis/bau). Everything it needs on
# the host is a directory, three keychain items Martin creates by hand, a
# checkout, and its own install.sh (venv, agent image, egress proxy, launchd).
- name: Create the BAU root
  ansible.builtin.file:
    path: "{{ bau_root }}/{{ item }}"
    state: directory
    mode: "0755"
  loop: [repos, work, logs]

- name: Check the BAU keychain items exist
  ansible.builtin.command:
    argv: [security, find-generic-password, -s, bau, -a, "{{ item }}"]
  loop: "{{ bau_keychain_items }}"
  register: _bau_keychain
  changed_when: false
  failed_when: false

- name: Refuse without the BAU keychain items
  ansible.builtin.fail:
    msg: |
      Keychain item bau/{{ item.item }} is missing. At the console, as nakomis:
        security add-generic-password -s bau -a {{ item.item }} -w '<value>'
      (github-app-key takes the PEM: -w "$(cat nakomis-bau.private-key.pem)";
       claude-oauth-token comes from `claude setup-token`.)
  loop: "{{ _bau_keychain.results }}"
  when: item.rc != 0

- name: Check out nakomis/bau
  ansible.builtin.git:
    repo: "{{ bau_repo }}"
    dest: "{{ bau_root }}/src"
    version: "{{ bau_ref }}"
    accept_newhostkey: true
  register: _bau_checkout

- name: Install or update BAU
  ansible.builtin.command:
    argv: ["{{ bau_root }}/src/install.sh"]
    chdir: "{{ bau_root }}/src"
  environment:
    PATH: "/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin"
    DOCKER_HOST: "unix://{{ cere_home }}/.colima/default/docker.sock"
  register: _bau_install
  changed_when: "'Installed.' in _bau_install.stdout and _bau_checkout.changed"

- name: Confirm the BAU launchd jobs are loaded
  ansible.builtin.command:
    argv: [launchctl, print, "gui/{{ ansible_user_uid }}/com.nakomis.{{ item }}"]
  loop: [bau-run, bau-snapshot, bau-api]
  changed_when: false
```

Include it from the playbook after the Colima and runner sections:
```yaml

      ansible.builtin.include_tasks: tasks/bau.yml
      tags: [bau]
```

### Task 3: Terraform for the GitHub App installation

> **Dropped 14 Oct 2026.** GitHub refuses App installation tokens and gh OAuth tokens on the installation-repositories endpoints; only a classic PAT or a user-to-server token works. Martin chose to manage the App's repository list by hand. The rest of this task is kept for the record only.

**Files:**
- Create: `terraform/main.tf`, `terraform/variables.tf`, `terraform/repos.tf`, `terraform/scripts/app-key.sh`, `terraform/Makefile`, `terraform/README.md`; add `terraform/.terraform/`, `terraform/*.tfstate*` to `.gitignore`

- [ ] **Step 1: `main.tf`**

```hcl
terraform {
  required_version = ">= 1.9"
  required_providers {
    github = { source = "integrations/github", version = "~> 6.0" }
  }
}

# The provider authenticates as the App itself, so no personal token is involved.
data "external" "app_key" {
  program = ["${path.module}/scripts/app-key.sh"]
}

provider "github" {
  owner = "nakomis"
  app_auth {
    id              = var.app_id
    installation_id = var.installation_id
    pem_file        = data.external.app_key.result.pem
  }
}

data "github_app" "bau" {
  slug = "nakomis-bau"
}

output "app" {
  value = { id = var.app_id, installation_id = var.installation_id, name = data.github_app.bau.name }
}
```

- [ ] **Step 2: `variables.tf`, `repos.tf`, the key script**

```hcl
# variables.tf
variable "app_id"          { type = number }
variable "installation_id" { type = number }
variable "repositories" {
  description = "Repos BAU may work in. Keep in step with config/projects.yaml."
  type        = set(string)
  default     = ["bau", "home-infra"]

```

```hcl
# repos.tf
resource "github_app_installation_repository" "bau" {
  for_each        = var.repositories
  installation_id = tostring(var.installation_id)
  repository      = each.value
}
```

```bash
#!/usr/bin/env bash
# terraform/scripts/app-key.sh: hand the App private key to the provider from the keychain.
set -euo pipefail
if ! pem=$(security find-generic-password -s bau -a github-app-key -w 2>/dev/null); then
  echo 'keychain item bau/github-app-key is missing: security add-generic-password -s bau -a github-app-key -w "$(cat key.pem)"' >&2
  exit 1
fi
python3 -c 'import json,sys; print(json.dumps({"pem": sys.stdin.read()}))' <<< "$pem"
```
